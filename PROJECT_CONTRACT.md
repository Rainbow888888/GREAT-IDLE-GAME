# GREAT-IDLE-GAME — контракт проекта

Версия: 0.1 · Дата: 2026-09-20 · Статус: документация, кода нет

Рабочее название сеттинга: **The Wreck** (гипотеза, см. Q-001 в `docs/DECISION_LOG.md`).
Если старые тексты или чаты противоречат этому файлу — действует этот файл.

## 1. Что за игра

Короткая guided-incremental игра с конечным финалом и престижами.
Колония людей разбирает на части огромный упавший корабль. Корабль сопротивляется.
Каждый пробитый слой — EMP, откат поселения и престиж. Пятый забег — финал.

До завершения этапа 5 обязательство проекта — только качественный забег I.
Пять забегов — продуктовая гипотеза, которую нельзя превращать в код заранее.

Формула: **структура Slimeward + сжатие старого как в Digseum + плотность покупок
Nodebuster + слоистые системы Tower Wizard — без их лишней длины.**

## 2. Центральное обещание игроку

> Я всегда понимаю, чего хочу следующим, и всегда чувствую, что расту.

Каждая механика проверяется этой фразой. Если механика её ломает — механики нет.

## 3. Жёсткие рамки масштаба

| Параметр | Значение |
|---|---|
| Первое прохождение, медиана | 4:30–5:00 |
| Быстрый игрок | 3:30–4:00 |
| 100% | 6–7 часов, не больше |
| Основных ресурсов | 4 (Scrap, Power, Alloy, Core Material) |
| Основных зданий | 10, у каждого 6 уровней |
| Престижей / забегов | целевой продукт: 4 / 5; до гейта этапа 5: 0 / 1 |
| Крупных апгрейдов | целевой продукт: ~30; сейчас только нужные забегу I |
| Мелких апгрейдов | на старте 0, добавлять только по данным плейтеста, потолок ~40 |
| Финал | настоящий. Endless после финала — опционально, после релиза |

Правило: Slimeward ×1.15 по объёму, а не ×3.

## 4. Законы темпа

- Первый работник < 45 сек. Первая автоматизация < 8 мин. Prestige I на 28–35 мин.
- В первый час не больше 6–8 минут без нового визуального или механического события.
  Дальше — не больше 12 минут.
- Ни одной ситуации «просто копи 5 минут» без второго осмысленного занятия.
- **Повтор старого контента после престижа — не больше 6 минут в любом забеге.**
  Свежий пройденный слой игрок переигрывает сам («я бог»), всё более старое
  восстанавливается автоматически за 30–60 сек анимации (D-003).
- Поздняя игра ускоряется, а не замедляется.
- Цена разблокировки считается через время ожидания: `Cost = Income × TargetWait`.

## 5. Законы престижа

- Престиж — сюжетная граница (пробит слой корабля), а не гринд очков.
- Каждый престиж даёт гарантированный новый постоянный слой.
- Выбор при престиже допускается, только если варианты меняют то, чем игрок занят,
  а не два числа. Не получается — выбора нет (D-005).
- Никакой обязательной частой кнопки ради ×N на секунды (D-004).

## 7. Технические законы

- Unity `6000.3.24f1`, 2D, URP, C#. Проект нельзя открывать в другой версии.
- Экономика — чистый C# без `UnityEngine`, покрыта EditMode-тестами.
- Числа — в JSON-конфиге. Один источник чисел для игры и для симулятора баланса.
- Одна маленькая bootstrap-сцена. Менеджеры создаются кодом; визуальные объекты и UI
  можно хранить в префабах, чтобы нормально настраивать текстуры и анимации.
- Агенты не редактируют YAML сцен/префабов как обычный текст: изменения делаются
  через Unity Editor/Editor-скрипт и проверяются в Play mode.
- Git LFS включается до первого тяжёлого арта, не после.
- Визуальную приёмку делает только владелец и только по свежей сборке/Play mode.

## 8. Кто что делает

Подробно — `docs/WORKFLOW.md`. Коротко: владелец решает и принимает визуал;
Kimi реализует; Codex ведёт архитектуру и ставит главный вердикт по ревью;
Claude даёт независимую критику на гейтах или по запросу.

## 9. Главный принцип

Лучше меньшая законченная игра, чем большая незавершённая.
Нельзя растягивать игру гриндом, ожиданием, HP-губками или повтором ради часов.
