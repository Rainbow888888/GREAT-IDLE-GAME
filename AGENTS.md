# SLIMEWARD2.0 — правила работы агента

Короткая incremental-игра с престижем. Главный ориентир — Slimeward.
Unity строго `6000.3.24f1`, 2D, C#. Владелец — Кларус. Всё общение на русском.

Этот файл OpenCode читает автоматически. Он для кодера и ревьювера.
Архитектор и внешние ревьюверы (ChatGPT, Claude) читают его тоже.

## Порядок чтения

1. Файл текущей задачи из `docs/tasks/` — если он назван, он главный.
2. `NEXT_CHAT.md` — снимок состояния и текущий этап.
3. `ROADMAP.md` — этапы. Работать можно только в рамках текущего этапа.
4. `PROJECT_CONTRACT.md` — законы игры и запреты.
5. `docs/BALANCE.md` — только если задача трогает числа, формулы, темп.
6. `docs/DECISION_LOG.md` — принятые решения и открытые вопросы.
7. `docs/UNITY_PITFALLS.md` — перед любой задачей со сценой, UI, сборкой, шрифтами, вводом.

Весь `docs/` целиком не читать.

## Границы

- Одна задача = одно наблюдаемое изменение. Формат `дано → действие → результат`.
- Не выходить за границы файла задачи и текущего этапа `ROADMAP.md`.
  Идея, не нужная этому шагу, пишется в `docs/DECISION_LOG.md` (раздел «Идеи»)
  и не реализуется «раз уж рядом».
- Не рефакторить соседний работающий код без дефекта.
- Не строить абстракции на будущее. Никаких фреймворков «под пять забегов».
- Числа баланса живут в JSON-конфиге (`Assets/Game/Resources/balance/`), не в коде.
  Магическое число в коде — дефект.
- Экономика — чистый C# без `UnityEngine` (папка `Assets/Game/Scripts/Core`).
  Визуал только читает состояние экономики и отправляет в неё команды.
- Корневые спеки (`PROJECT_CONTRACT.md`, `ROADMAP.md`, `docs/BALANCE.md`)
  не править без явной команды владельца.
- Если задача противоречит спеке — остановиться и сказать об этом, код не писать.

## Тесты

- Тест, который пройдёт при заведомо неправильной реализации, — дефект.
  Проверка: выпотроши проверяемый метод — тест обязан покраснеть.
- Проверять равенство ожидаемому, а не «хоть что-то произошло».
- Литерал, дублирующий вычисляемое значение (заглушка «на всякий случай»), — дефект.
- Прогон EditMode в batch, редактор Unity должен быть закрыт:

```
O:\UNITY\6000.3.24f1\Editor\Unity.exe -batchmode -nographics -projectPath O:\AI\SLIMEWARD2.0 -runTests -testPlatform EditMode -testResults Logs\results.xml -logFile Logs\tests.log
```

Не добавлять `-quit` к `-runTests`.

## Отчётность

- «Готово», «записано», «исправлено» — не факт. Перед такими словами перечитай
  изменённый файл с диска и убедись, что изменение в нём есть.
- Успешный ответ инструмента записи — не подтверждение. Подтверждение — чтение.
- В отчёте называть файл и то, что в нём проверено, а не список намерений.
- Агент не видит картинку. Всё визуальное принимает владелец глазами,
  только по свежей сборке или в Play mode.

## Git

- Кодер коммитит только по команде владельца. Пуш — никогда без отдельной команды.
- `git add -A` не использовать. Добавлять поимённо только файлы этой задачи.
- `git reset --hard`, `push --force` не предлагать и не выполнять.
- Папка `for GPT/` в репозиторий не идёт.
- Исключение: архитектор (Claude) правит документацию и сразу пушит её —
  это постоянная команда владельца. Код архитектор не коммитит.

## После рабочего коммита — обязательно напомнить владельцу

Ровно тремя пунктами, коротко:

1. Сессия набрала большой контекст — закрыть (`/new`) и открыть новую под следующую задачу.
2. `NEXT_CHAT.md` устарел и должен быть переписан до следующего шага.
3. Снять расход: `opencode stats --project "" --days 7 --models`.

Напоминание даётся один раз после коммита, без повторов.
