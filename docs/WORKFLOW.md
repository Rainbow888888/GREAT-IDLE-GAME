# Оркестрация — регламент

Постоянный файл. Не устаревает после коммита (в отличие от `NEXT_CHAT.md`).
Перенесён из Stratosphere2 (`docs/OPENCODE_WORKFLOW.md`) с поправкой на трёх ревьюверов.

## Роли

| Роль | Кто | Что делает | Чего не делает |
|---|---|---|---|
| Владелец | Кларус | решает, принимает глазами, коммитит код, пушит | — |
| Архитектор | Claude (Cowork, папка подключена) | спеки, постановки в `docs/tasks/`, финальное ревью, `NEXT_CHAT.md`, пушит доки | не пишет игровой код, не коммитит код |
| Кодер | OpenCode, `opencode-go/kimi-k2.7-code` | код, тесты, batch-прогоны, сборка | не ставит себе задачи, не пушит |
| Ревьювер 1 | OpenCode субагент `@reviewer`, `opencode-go/deepseek-v4-pro` | дифф против задачи, честность тестов | не редактирует, не запускает |
| Ревьювер 2 | ChatGPT (доступ к папке проекта) | независимое ревью по файлам | не правит код и спеки |
| Ревьювер 3 | Claude-архитектор | финальное ревью: спека, этап, баланс, архитектура | — |

Ни один агент не коммитит и не пушит код по своей инициативе.

## Цикл одной задачи

1. **Архитектор** пишет `docs/tasks/<ID>.md` по шаблону `_TEMPLATE.md` и пушит.
   Устно задачи не ставятся. Перед постановкой — проверка выполнимости на
   существующих данных (дороже любого бага, ловится до кода).
2. **Владелец** открывает новую сессию OpenCode (`/new`) и даёт стартовый промпт
   (`docs/PROMPTS.md` §1).
3. **Кодер** читает `AGENTS.md`, задачу, дальше по порядку чтения. Пишет код и тесты,
   прогоняет EditMode в batch.
4. **Кодер** проверяет тесты тестом: выпотрошить метод, тесты краснеют, вернуть.
5. **Ревьювер 1 (DeepSeek)** — обязательно: `@reviewer`, в запросе дифф и результат
   прогона текстом (`docs/PROMPTS.md` §2). Максимум один круг исправлений, дальше `STOP`.
   Кодер сохраняет ответ в `docs/reviews/<ID>/deepseek.md`.
6. **Ревьювер 2 (ChatGPT)** — по файлам в папке, промпт `docs/PROMPTS.md` §3.
   Ответ сохраняется в `docs/reviews/<ID>/chatgpt.md`.
7. **Ревьювер 3 (Claude)** — читает задачу, дифф (`git diff`), оба ревью, проверяет
   по файлам, а не по отчётам. Пишет `docs/reviews/<ID>/claude.md` с вердиктом
   `ACCEPT` / `FIX` / `STOP`. Разногласия ревьюверов разбирает здесь же.
8. **Владелец** принимает глазами то, что видно только глазами — по свежей сборке
   или в Play mode. Задача обязана назвать, чем делается визуальная приёмка.
9. **Владелец** коммитит поимённо и пушит. `git add -A` не использовать.
10. **Архитектор** переписывает `NEXT_CHAT.md`, отмечает прогресс в `ROADMAP.md`
    (статус этапа меняет только по слову владельца), пушит доки. Владелец снимает расход.

### Когда можно облегчить ревью

По умолчанию все три ревьюера на каждой задаче. Владелец может пометить задачу
в шапке `Ревью: лёгкое` — тогда только DeepSeek + Claude. Для задач на закрытие этапа
(гейт) облегчение запрещено.

### Если ревьюверы расходятся

Решает не большинство, а сценарий отказа: находка с конкретным «вход → неверный
результат» весит больше мнения. Спор об архитектуре без сценария отказа — к владельцу.

## Синхронизация папки и GitHub

- Локальная папка: `O:\AI\SLIMEWARD2.0`. GitHub: `Rainbow888888/SLIMEWARD2.0` (private).
- **Источник правды — локальная папка.** GitHub — её копия.
- Архитектор (Claude в Cowork) пишет файлы прямо в `O:\AI\SLIMEWARD2.0` и даёт владельцу
  готовые команды `git add <файлы>` / `git commit` / `git push`. Через GitKraken MCP
  архитектор коммитит только по прямой просьбе владельца.
- Ограничения среды Claude (проверено 2026-09-20): облако не может создать репозиторий
  на GitHub и не может писать внутрь `.git` на машине; shell на машине в Cowork может
  не запуститься. Поэтому git — только через GitKraken или руками владельца.
- Перед любой правкой — `git_pull`/`git_status`. Незакоммиченные чужие изменения
  не трогать и не включать в свой коммит.
- Конфликт — не решать силой. Остановиться и показать владельцу.

## Сессии и расход (из опыта Stratosphere2)

- Новая сессия OpenCode под каждую задачу, закрывается после рабочего коммита.
  Стоимость запроса = размер входа, а вход в сессии только растёт.
- `/new` — новая, `/sessions` — список, `/compact` — сжать (детали теряются молча;
  между задачами лучше `/new`).
- Prompt cache живёт ~5 минут. Первый запрос после паузы > 5 мин в Stratosphere
  стоил в ~4.7 раза дороже соседей (замер на 3 точках, не тариф). Выводы:
  - работать плотными блоками;
  - после долгой паузы дешевле `/new`, чем возвращаться в раздутую сессию;
  - после паузы первое сообщение агенту — содержательная задача, не «покажи статус»;
  - `git add/commit/push/status` и запуск сборки владелец набирает сам.
- Warming (`"warming"` в конфиге) по умолчанию не включать; если включать —
  с `duration` ~12 минут. Пересчитать на своих числах.
- Кэш также ломают: правка системного промпта, смена набора инструментов/MCP,
  плагины, дописывающие текст в каждый запрос.

Замер расхода:

```
opencode stats --project "" --days 7 --models
opencode session list -n 10
```

В `NEXT_CHAT.md` после задачи — одна строка: запросы и сумма отдельно по кодеру
и по ревьюверу. Смотреть тренд и отношение вход/выход: 100k входа при 50 токенах
выхода — платится контекст, а не работа.

Ориентир из Stratosphere2 (Gate A.2): кодер 26 запросов / $1.49, ревьювер 5 / $0.04.

## Лимиты моделей (Go-тир, на сентябрь 2026 — сверять `/models`)

- `kimi-k2.7-code` — ~1350 запросов на 5-часовое окно.
- `deepseek-v4-pro` — ~1050 на окно.
- Месячный кап ≈ 5 окон, недельный ≈ 2.5. Лимиты по моделям раздельные —
  поэтому роли разнесены по разным моделям.
- Запасные и резервные модели — комментариями в `opencode.jsonc`.

## Проверка при смене модели ревьювера

В трекере OpenCode были противоречивые баги про наследование модели субагентом.
После первого прогона нового ревьювера смотреть `stats --models`: если списалось
по модели кодера — ревью шло той же головой, что писала код, и оно обесценено.
