Репозиторий распознаётся Unity `6000.3.24f1` как 2D-проект, импортируется без
compile errors, а EditMode-тест загружает существующий `run1.json` через
`Resources` + `JsonUtility` и проверяет конкретные значения.

Это ещё не весь этап 2: сцена, URP и Windows build относятся к S2.2.

Разрешённый diff: новые `Packages/**`, `ProjectSettings/**`, перечисленные ниже
`Assets/Game/{Core,Runtime,Tests}/**` и созданные Unity `.meta` для существующей
структуры `Assets/`. Другие существующие файлы не менять.

## 2. Создать проект безопасно

1. Убедиться, что `O:\AI\GREAT-IDLE-GAME-BOOTSTRAP` не существует. Если существует —
   остановиться, не удалять чужую папку.
2. Если `unity editors --installed --format json` не видит `6000.3.24f1`, зарегистрировать
   существующий Editor через `unity editors add O:\UNITY\6000.3.24f1\Editor\Unity.exe`.
3. Создать временный проект официальным шаблоном:

```powershell
unity projects create GREAT-IDLE-GAME-BOOTSTRAP --path O:\AI --editor-version 6000.3.24f1 --template com.unity.template.2d --no-cloud --non-interactive
```

4. Перенести из временного проекта в корень репозитория только `Packages/` и
   `ProjectSettings/`. Шаблонную сцену и прочее содержимое временного `Assets/`
   не переносить: целевой `Assets/` уже существует и будет импортирован Editor.
5. После успешного импорта удалить только созданную этой задачей папку
   `O:\AI\GREAT-IDLE-GAME-BOOTSTRAP`.

Если CLI не может создать проект из-за лицензии или регистрации Editor — остановиться
с точным выводом. Не имитировать Unity-проект вручную.

## 3. Минимальная структура кода

Создать:

- `Assets/Game/Core/Game.Core.asmdef` с `noEngineReferences=true`;
- DTO конфига в `Game.Core`, достаточные для чтения всего `run1.json`;
- `Assets/Game/Runtime/Game.Runtime.asmdef`, ссылающийся на `Game.Core`;
- runtime-loader, который читает `Resources.Load<TextAsset>("balance/run1")` и
  десериализует через `JsonUtility`;
- `Assets/Game/Tests/Editor/Game.Tests.Editor.asmdef` для EditMode и один тест
  `Run1ConfigLoadsFromResources`.

Тест обязан проверить как минимум:

- `schemaVersion == 1`;
- `maxSeconds == 2400`;
- `prestigeMultiplier == 7.96f` с tolerance `0.0001f`;
- `buildings.Length == 4` и `buildings[0].id == "salvage_rig"`;
- `fixedPurchases.Length == 7`;
- последняя покупка имеет `id == "emp"` и `endsRun == true`.

Публичные JSON-поля в DTO должны совпадать с ключами JSON. Для ключа `yield`
использовать допустимый C#-идентификатор `@yield`, не менять JSON.

## 4. Проверки

Запустить Editor напрямую в batch, чтобы использовалась точная версия:

```powershell
O:\UNITY\6000.3.24f1\Editor\Unity.exe -batchmode -nographics -projectPath O:\AI\GREAT-IDLE-GAME -runTests -testPlatform EditMode -testResults Logs\s2.1-results.xml -logFile Logs\s2.1-tests.log
```

Не добавлять `-quit`. Затем проверить:

- тест `Run1ConfigLoadsFromResources` прошёл;
- в логе нет compile errors;
- `ProjectSettings/ProjectVersion.txt` содержит `6000.3.24f1`;
- `Library/`, `Temp/`, `Logs/`, `.csproj`, `.sln` не попали в Git;
- каждый новый файл в `Assets/` имеет созданный Unity `.meta`;
- `git diff -- Assets/Game/Resources/balance/run1.json` пуст.

Mutation-check: временно заменить в тесте ожидаемые `2400` на `2401`, убедиться,
что именно этот тест падает, затем вернуть `2400` и повторить зелёный прогон.
