## 0. Результат задачи

Чистый проект S2.1 переводится с Built-in на **URP 2D**, получает одну созданную
Unity API bootstrap-сцену и воспроизводимую Windows x64 сборку. При запуске `.exe`
на тёмном пустом экране виден центрированный текст `GREAT IDLE GAME`.

Это инфраструктурная задача: игровой цикл и баланс в C# не реализуются.

## 1. Preflight и границы миграции

Перед изменениями:

1. подтвердить чистый HEAD `08e627e` и синхронность с `origin/main`;
2. проверить через Unity API: активный pipeline — Built-in, Quality levels не имеют
   pipeline override;
3. подтвердить отсутствие сцен, материалов, пользовательских шейдеров, PPv2,
   baked lighting и reflection probes в `Assets/`;
4. убедиться, что другой Unity Editor не держит этот проект открытым.

Коммит `08e627e` — подтверждённая rollback-точка. Это миграция нового пустого 2D-проекта,
поэтому material converter, PPv2 converter и lighting bake запускать не требуется.

Не редактировать `.unity`, `.asset`, `.prefab`, `manifest.json` или ProjectSettings YAML
как текст. Пакеты меняются через `UnityEditor.PackageManager.Client`, ассеты, сцена и
PlayerSettings — через Unity Editor API.

## 2. Минимальные пакеты

Одним `Client.AddAndRemove` оставить прямыми зависимостями только нужное этому проекту.

Добавить:

- `com.unity.render-pipelines.universal`;
- `com.unity.2d.sprite`;
- `com.unity.2d.animation`.

Сохранить уже установленные:

- `com.unity.inputsystem`;
- `com.unity.test-framework`;
- `com.unity.ugui` (включая TextMeshPro).

Удалить прямые зависимости шаблона:

- `com.unity.feature.2d` — он преждевременно тянет Aseprite и Pixel Perfect;
- `com.unity.collab-proxy`;
- `com.unity.ide.rider`;
- `com.unity.ide.visualstudio`;
- `com.unity.multiplayer.center`;
- `com.unity.timeline`;
- `com.unity.visualscripting`.

Built-in `com.unity.modules.*` не чистить вручную. Для установки использовать временный
`Assets/Editor/ProjectBootstrap/PackageInstaller.cs` по асинхронному update-callback
паттерну. Editor запускать напрямую **без `-quit`**; скрипт сам вызывает
`EditorApplication.Exit`. После успешной установки удалить временный installer и его `.meta`.

После domain reload сначала проверить `manifest.json` и `packages-lock.json`; не запускать
установку повторно, если URP уже установлен.

## 3. Воспроизводимый Editor setup

Создать `Assets/Game/Editor/Game.Editor.asmdef` (только Editor, ссылки на `Game.Core`
и `Game.Runtime`) и идемпотентный `ProjectSetup.cs` с публичным методом `Run`.

`Run` обязан через Unity API:

1. импортировать только TMP Essentials неинтерактивно через
   `TMPro.TMP_PackageResourceImporter.ImportResources(true, false, false)`; не открывать
   меню и модальные окна;
2. создать под `Assets/Game/Rendering/` один `Renderer2DData` и один
   `UniversalRenderPipelineAsset`, назначить 2D renderer default renderer'ом;
3. назначить тот же URP asset в Graphics settings и **явно во всех** Quality levels;
4. установить:
   - `PlayerSettings.companyName = "Klarus"`;
   - `PlayerSettings.productName = "GREAT IDLE GAME"`;
   - Standalone application identifier `com.klarus.greatidlegame`;
   - Input handling: только Input System, не Both;
5. создать и сохранить `Assets/Game/Scenes/Bootstrap.unity`:
   - `MainCamera`, orthographic, фон `#101318`, позиция `(0,0,-10)`;
   - `Canvas`, Screen Space Overlay;
   - `CanvasScaler`: Scale With Screen Size, `1920×1080`, match `0.5`;
   - `GraphicRaycaster`;
   - дочерний `Title` с `TextMeshProUGUI`, текстом `GREAT IDLE GAME`, белым цветом,
     размером шрифта `72`, центрированием, `raycastTarget=false`;
   - `Title` закреплён по центру и имеет ненулевой размер не меньше `900×160`;
   - `EventSystem` не создавать: интерактивных элементов пока нет;
6. сделать Bootstrap единственной включённой сценой в Build Settings;
7. сохранить ассеты и сцену, перечитать созданные URP assets и завершиться ошибкой,
   если default renderer отсутствует или не является 2D renderer.

Все UI-типы в Editor-коде указывать полностью: `UnityEngine.UI.CanvasScaler`,
`UnityEngine.UI.GraphicRaycaster` и т. п.

## 4. Windows build

Создать `Assets/Game/Editor/BuildWindows.cs` с публичным batch entry point.
Он собирает единственную Bootstrap-сцену для `StandaloneWindows64` в:

```text
Builds/Windows/GREAT-IDLE-GAME.exe
```

`Builds/` остаётся ignored. Не коммитить бинарники и логи. При неуспешном
`BuildReport.summary.result` метод обязан завершить batch ненулевым кодом.

## 5. Тесты

Сохранить тест S2.1 и добавить ровно один EditMode-тест
`BootstrapProjectContractIsSaved` (итого **2**). Он проверяет сохранённое состояние:

- Graphics использует `UniversalRenderPipelineAsset`;
- asset имеет ненулевой default renderer, renderer data — `Renderer2DData`;
- каждый Quality level явно ссылается на тот же URP asset;
- Build Settings содержит ровно одну включённую `Assets/Game/Scenes/Bootstrap.unity`;
- сцена открывается, содержит ровно одну Main Camera и один Canvas;
- Canvas/Scaler/GraphicRaycaster настроены по §3;
- `Title` содержит `TextMeshProUGUI`, точный текст, `fontSize=72`, белый цвет,
  `raycastTarget=false` и ненулевой RectTransform;
- `PlayerSettings` имеют значения из §3, active input handling — Input System only.

Mutation-check: временно ожидать `GREAT IDLE GAMES`, получить падение именно нового
теста, вернуть строку и повторить зелёный прогон.

## 6. Команды и проверка

После package phase выполнить setup отдельным Editor-запуском; затем:

```powershell
unity test O:\AI\GREAT-IDLE-GAME --editor-version 6000.3.24f1 --mode EditMode --report-format nunit --output Logs\s2.2-results.xml --timeout 600
```

Собрать через `BuildWindows` и запустить:

```powershell
O:\AI\GREAT-IDLE-GAME\Builds\Windows\GREAT-IDLE-GAME.exe
```

Перед отчётом повторно проверить через Unity API и файлы:

- активный pipeline и все Quality levels;
- URP asset имеет валидный 2D renderer;
- Console/build log без compile, renderer и shader errors;
- сцена сохранена и входит в Build Settings;
- все новые `Assets/` имеют `.meta`;
- generated folders и build не staged.
