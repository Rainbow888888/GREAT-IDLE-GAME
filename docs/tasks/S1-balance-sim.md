# S1 — минимальный симулятор забега I

Этап: 1 · Исполнитель: Kimi/OpenCode · Главное ревью: Codex
Визуальная приёмка: не требуется

## Результат

Команда

```powershell
python tools/sim/sim.py --config Assets/Game/Resources/balance/run1.json
```

печатает детерминированный таймлайн базового маршрута забега I и итоговую таблицу:
первый рабочий, автоматизация доставки, EMP, максимальное окно между meaningful-событиями.

Симулятор проверяет арифметику и хрупкость чисел. Он не доказывает, что игра интересна
или что живой игрок будет покупать именно так.

## Файлы

- `Assets/Game/Resources/balance/run1.json` — только игровые данные, совместимые с
  Unity `JsonUtility`: объект верхнего уровня, массивы объектов, без словарей.
- `tools/sim/run1-plan.json` — последовательность целей базового маршрута; содержит
  только id и количество/уровень, без цен и производства.
- `tools/sim/sim.py` — стандартная библиотека Python, без внешних зависимостей.
- `tools/sim/test_sim.py` — `unittest`.
- `tools/sim/README.md` — две команды запуска и объяснение ограничений модели.

## Модель

- Шаг симуляции — 1 секунда.
- До автоматизации бот выполняет ручное действие сразу после cooldown.
- Покупки идут строго по `run1-plan.json`: бот копит на текущую цель и покупает её
  сразу, когда хватает ресурсов. Это явный intended path, а не «ИИ игрока».
- После каждой покупки и сюжетного события пишутся время, id и категория:
  `routine`, `unlock`, `visual` или `mechanical`.
- Отдельно прогоняются `income ×0.9`, `×1.0`, `×1.1`. Только `×1.0` обязан попасть
  в целевые коридоры; боковые прогоны показывают чувствительность.
- Флаг `--prestige-multiplier N` повторяет тот же маршрут и сообщает длительность.
  Если она больше 6 минут, отчёт печатает минимальный требуемый множитель.

Конкретные поля JSON и начальные числа исполнитель выбирает минимальными, достаточными
для Scrap, ручного действия, рабочих, 4 зданий, авто-доставки, первой угрозы и EMP.
Формулы и категории — `docs/BALANCE.md` §§3, 5, 9.

## Обязательные тесты

1. `WorkerCost`: при `B=10`, `growth=1.17` стоимости n=0 и n=1 равны `10` и `11.7`.
2. `BuildingLevel`: при baseCost=100 и baseOutput=5 уровни L1/L2 дают стоимость
   `100/240` и output `5/8`.
3. `WorkerMilestone`: при count=10 итоговый множитель `1.75`, не `1.5×1.75`.
4. `Determinism`: два запуска одной фикстуры дают одинаковый таймлайн.
5. `ConfigIsUsed`: изменение ручного yield в копии фикстуры меняет время первой покупки.
6. `Run1Targets`: базовый конфиг даёт первого рабочего <45 сек, авто-доставку <8 мин,
   EMP в 28–35 мин и окно без `unlock/visual/mechanical` <8 мин.

Запуск:

```powershell
python -m unittest tools.sim.test_sim -v
```

## Приёмка

- все шесть тестов проходят;
- базовый отчёт попадает в четыре коридора выше;
- отчёт для `×0.9` и `×1.1` печатается рядом и явно помечен как sensitivity;
- найден или вычислен prestige multiplier, при котором повтор ≤6 минут;
- изменение JSON влияет на результат без правки Python;
- Codex проверил diff и записал `docs/reviews/S1-balance-sim/codex.md`.
