# Задача S1 — симулятор баланса забега I

Создано: 2026-09-20 · Этап: 1 · Исполнитель: **архитектор (Claude)**, не кодер
Ревью: ChatGPT + владелец (кода Unity нет, DeepSeek не нужен)

## 0. Что нужно знать

Игры ещё нет. Цель — поймать ошибки чисел до первой строчки C#.
Пример того, что ловится: формула повтора в исходном балансе давала 5:10 вместо 4:40 (D-003).

## 1. Результат

`python tools/sim/sim.py` печатает таймлайн забега I (0–35 мин): время каждой покупки
и события, и сводку по метрикам `docs/BALANCE.md` §9 с пометкой «в коридоре / вне».

## 2. Что сделать

- `Assets/Game/Resources/balance/run1.json` — первая версия чисел забега I:
  ресурс Scrap, ручной клик, рабочие (база, рост 1.17, вехи 5/10/20),
  4–5 зданий (базовая цена, рост 2.4, отдача 1.6, уровни 1–6), апгрейды забега I,
  события корабля (условие → время), первая угроза, EMP.
  Формат JSON пригоден для чтения из C# (`JsonUtility`: без словарей верхнего уровня,
  массивы объектов с `id`).
- `tools/sim/sim.py` — читает JSON, шаг 0.1–1 сек, бот с жадной стратегией
  «покупай самое дешёвое по сроку окупаемости», таймлайн + сводка.
- `tools/sim/replay.py` или флаг — прикидка повтора забега I после престижа
  при заданном множителе (проверка бюджета ≤ 6 мин, D-003).
- `tools/sim/README.md` — как запускать, что значат колонки.

## 3. Проверки

- Первый работник < 45 сек, первая автоматизация < 8 мин, EMP в 28–35 мин.
- Нет окна > 8 мин без покупки/события.
- Повтор забега I после престижа ≤ 6 мин.
- Смена одного числа в JSON меняет таймлайн (симулятор реально читает конфиг).

## 4. Запрещено

Unity-проект, C#, забеги II–V в деталях, арт.
